# 언어별 함정

**대상 언어 절만 읽어라.** 전부 읽으면 컨텍스트만 먹는다.

공통으로 기억할 것 하나: **길이 검사는 글자 수를 세지만 화면은 픽셀을 쓴다.**
CJK 는 글자 수가 줄어도 전각이라 실제로는 넓다. 길이 검사를 통과해도 의사 현지화로
한 번 봐야 한다.

---

## 독일어 (de)

| | |
|---|---|
| **길이** | 평균 **20~35% 증가**, 짧은 문자열은 **2배**까지. `Settings` → `Einstellungen` |
| **존대** | UI 는 보통 **`Sie`(존칭)**. `du` 는 게임·청소년 서비스가 아니면 어색하다. **문서 전체에서 하나로 통일** |
| **복합어** | 명사를 붙여 긴 단어를 만든다. 줄바꿈이 안 돼 단추가 터지는 주된 원인 |
| **명사 대문자** | 모든 명사가 대문자로 시작한다. 소문자로 쓰면 틀린 것이다 |
| **어순** | 동사가 뒤로 간다. 번호 없는 플레이스홀더(`%s`)는 순서를 못 바꾸니 문장을 다시 짜야 할 수 있다 |

🔑 **영어 능력이 높다고 영어로 파는 것이 아니다.** 독일 소비자 대다수가 모국어를
선호하고 현지화되지 않은 영어를 싫어한다. **정확성을 중시하는 시장**이라 어색한 번역의
대가가 크다.

## 일본어 (ja)

| | |
|---|---|
| **경어** | UI 는 **`です・ます`체**. `だ・である`체는 딱딱하고 무례하게 읽힌다. **통일이 생명** |
| **길이** | 글자 수는 줄지만 **전각이라 폭은 비슷하거나 넓다.** 글자 수 비율로 판단하면 틀린다 |
| **줄바꿈** | 띄어쓰기가 없어 아무 데서나 끊긴다. 금칙 처리가 없으면 어색한 위치에서 끊어진다 |
| **외래어** | 가타카나로 쓸지 한자어로 쓸지 갈린다. **플랫폼 용어집을 따르는 것이 안전** (예: `Settings` → 애플 `設定`) |
| **중점** | 열거에 `・` 를 쓴다. 쉼표를 그대로 옮기면 어색하다 |

⚠️ **반쪽으로 하면 안 된다.** 일본은 영어 노출로 닿지 않는 시장이라, UI 만 번역하고
스토어 설명·문의 대응을 영어로 두면 **번역 비용만 쓰고 전환이 안 난다.**

## 중국어 — 번체 (zh_Hant) · 간체 (zh_Hans)

**글자만 다른 것이 아니라 어휘가 다르다.** 자동 변환으로 때우면 어색해진다.

| 개념 | 번체 (대만·홍콩) | 간체 (본토·싱가포르·말레이시아) |
|---|---|---|
| software | 軟體 | 软件 |
| file | 檔案 | 文件 |
| network | 網路 | 网络 |
| program | 程式 | 程序 |

| | |
|---|---|
| **길이** | 가장 짧아진다. 대신 **전각**이라 폭은 덜 줄어든다 |
| **띄어쓰기** | 없다. 일본어와 같은 줄바꿈 문제 |
| **번체 안에서도** | 대만과 홍콩이 갈리는 어휘가 있다. 우선 대만 기준으로 하고 필요하면 나눈다 |
| **시장** | 번체는 **ICP 규제와 무관**하다. 간체는 본토 진입과 엮이므로 별개로 판단 |

## 프랑스어 (fr)

| | |
|---|---|
| **길이** | **15~25% 증가** |
| **존대** | UI 는 **`vous`**. `tu` 는 부적절 |
| **띄어쓰기** | `?` `!` `:` `;` 앞에 **좁은 비분리 공백**이 들어간다. 이걸 빼면 틀린 조판으로 보인다 |
| **아포스트로피** | `l'utilisateur` 처럼 자주 나온다. **Android XML 에서는 `\'` 로 이스케이프**해야 한다 — 안 하면 빌드가 깨진다 |
| **대문자** | 제목에서 영어처럼 각 단어를 대문자로 쓰지 않는다. 첫 글자만 |

🔑 프랑스는 **IPv6 보급이 세계 최고 수준**이라 P2P 직결 성공률이 높다. 원격 제어
제품이라면 일회성 티어가 가장 잘 먹히는 시장이다.

## 스페인어 — 스페인 (es) · 라틴아메리카 (es_419)

**파일을 둘로 나눠야 한다.** 어휘뿐 아니라 문법이 다르다.

| | 스페인 (es) | 라틴아메리카 (es-419) |
|---|---|---|
| computer | ordenador | computadora |
| mobile | móvil | celular |
| **2인칭 복수** | **vosotros** | **ustedes 만** |

UI 는 명령형이 많아서 2인칭 차이가 **문장마다 드러난다.** 하나로 때울 수 없다.

`es-419` 의 `419` 는 UN M.49 의 "라틴아메리카·카리브" 지역 코드다. 나라가 20개가
넘어 국가 코드를 못 쓰니 지역 코드를 쓴다.

| | |
|---|---|
| **길이** | 20~30% 증가 |
| **존대** | 보통 `usted`. 제품 성격에 따라 `tú` 도 쓰지만 **통일할 것** |
| **역물음표** | `¿…?` `¡…!` 로 감싼다. 앞쪽을 빼먹는 실수가 잦다 |

## 한국어 (ko)

| | |
|---|---|
| **길이** | 영어보다 짧아지는 편. 전각이라 폭은 덜 줄어든다 |
| **존대** | **`~합니다`체로 통일.** `~하세요`와 섞이면 어조가 흔들린다 |
| **조사** | 앞 글자 받침에 따라 `을/를` · `이/가` 가 갈린다. **플레이스홀더 뒤에 조사가 오면 값에 따라 틀린다** — `%1을(를)` 같은 형태로 피하거나 문장을 다시 짠다 |
| **어휘** | 억지 순화어·직역을 피하고 **실제로 쓰는 말**을 쓴다 |

## 새 언어를 추가할 때 확인할 것

| 항목 | 왜 |
|---|---|
| 존대 수준이 하나로 통일됐나 | 섞이면 아마추어로 읽힌다 |
| 복수형 형태 수가 맞나 | 언어마다 다르다 (영어 2 · 한국어 1 · 러시아어 3 · 아랍어 6) |
| 숫자·날짜·통화 형식 | **번역이 아니라 로케일 문제다.** 코드에서 `QLocale` 등에 맡긴다 |
| 텍스트 방향 | 아랍어·히브리어는 RTL. UI 미러링이 필요하고 작업량이 다른 차원이다 |
| 문자 렌더링 | CJK·아랍어는 폰트에 글리프가 있어야 한다. 없으면 □ 로 나온다 |
